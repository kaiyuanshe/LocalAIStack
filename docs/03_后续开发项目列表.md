# LocalAIStack 2.0 后续开发可参考、可引用、需要关注的项目列表

版本：0.1 Draft  
日期：2026-04-28  
用途：作为 LocalAIStack 2.0 的 upstream watchlist、选型参考与引用索引。

---

## 1. 选择原则

项目分三类：

1. **核心依赖**：第一阶段 Express 必须直接集成或适配。
2. **重要参考**：架构或能力值得学习，但第一阶段不一定直接依赖。
3. **持续关注**：可能成为 Expert 插件或后续优化方向。

评估维度：

- 开源活跃度
- 官方文档质量
- Docker/部署成熟度
- 本地可用性
- 硬件覆盖
- API 兼容性
- recipe 化难度
- 与 vLLM/SGLang/llama.cpp 的互补关系

## 2. LLM Inference Core

| 项目 | 分类 | 用途 | LocalAIStack 关注点 | 官方来源 |
|---|---|---|---|---|
| vLLM | 核心依赖 | GPU serving、高吞吐、OpenAI-compatible API | NVIDIA/AMD/CPU/XPU 支持矩阵，quant、attention、KV cache、batching 配置 | https://docs.vllm.ai/ |
| SGLang | 核心依赖 | 低延迟、高吞吐、prefix cache、结构化生成、Agent workload | RadixAttention、prefix caching、spec decoding、structured outputs、DeepSeek/Qwen 支持 | https://docs.sglang.ai/ |
| llama.cpp | 核心依赖 | GGUF、本地低依赖、CPU/Metal/CUDA/HIP/Vulkan/SYCL | GGUF quant、GPU offload、Metal、CPU、本地 server | https://github.com/ggml-org/llama.cpp |

### 引用建议

- vLLM：引用为 high-throughput and memory-efficient LLM inference/serving engine。
- SGLang：引用为 high-performance serving framework for LLM/VLM，强调 low-latency/high-throughput、RadixAttention 与 prefix caching。
- llama.cpp：引用为 minimal-setup local/cloud LLM inference in C/C++，强调 wide hardware backend 与 GGUF 生态。

## 3. Container 与 Runtime

| 项目 | 分类 | 用途 | LocalAIStack 关注点 | 官方来源 |
|---|---|---|---|---|
| Docker | 核心依赖 | Express recipe 运行载体 | compose、GPU access、volume、network、healthcheck | https://docs.docker.com/ |
| NVIDIA Container Toolkit | 核心依赖 | Docker 访问 NVIDIA GPU | nvidia-ctk、--gpus all、runtime config、diagnostics | https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/ |
| Docker Compose | 核心依赖 | 多服务 recipe 编排 | LLM + embedding + vector DB + UI | https://docs.docker.com/compose/ |
| ROCm Docker | 持续关注 | AMD GPU 容器运行 | /dev/kfd、/dev/dri、ROCm version、MI/Radeon 支持 | https://rocm.docs.amd.com/ |

### 关注点

- Linux/NVIDIA 应作为 Docker-first 主线。
- Apple Silicon 上 Docker 通常不是 Metal 推理的最佳载体，应保留 native recipe。
- Windows 需要区分 WSL2 Docker 与 native llama.cpp。

## 4. Kernel / Attention / Optimization

| 项目 | 分类 | 用途 | LocalAIStack 关注点 | 官方来源 |
|---|---|---|---|---|
| FlashAttention | 重要参考 | 高效 attention kernel | vLLM/SGLang 依赖兼容、长上下文、CUDA 版本 | https://github.com/Dao-AILab/flash-attention |
| FlashInfer | 重要参考 | LLM serving kernel library | attention、GEMM、MoE、paged attention、vLLM/SGLang 适配 | https://docs.flashinfer.ai/ |

### 关注点

这些不是 Express 第一阶段的产品对象，而是 engine recipe 的底层依赖和性能变量。Express 不应暴露这些开关；Expert 可以在 diagnostics 与 advanced recipe 中逐步纳入。

| LlamaIndex | 重要参考 | RAG data framework | data connectors、indexes、query engines、RAG pipeline | https://developers.llamaindex.ai/ |

| Haystack | 重要参考 | RAG/search pipeline | modular pipeline、retriever、generator、document store | https://docs.haystack.deepset.ai/ |

## 6. Vector DB / Search Index

| 项目 | 分类 | 用途 | LocalAIStack 关注点 | 官方来源 |

| 项目 | 分类 | 用途 | LocalAIStack 关注点 | 官方来源 |

| Hugging Face Text Embeddings Inference, TEI | 核心依赖候选 | embedding serving | Docker 化 embedding service、FlagEmbedding/E5/GTE 等模型服务 | https://huggingface.co/docs/text-embeddings-inference/ |

## 13. 推荐优先级

## P0：第一阶段必须盯紧

- vLLM
- SGLang
- llama.cpp
- Docker / Docker Compose
- NVIDIA Container Toolkit
- Qdrant
- TEI 或 sentence-transformers

## P1：RAG Express 需要

- LlamaIndex
- LangChain
- Haystack
- Docling
- PyMuPDF
- Ragas
- Elasticsearch/OpenSearch，若要 keyword/hybrid search

## P2：Expert 阶段逐步纳入

- FlashInfer
- FlashAttention
- Triton language
- TileLang
- ExLlamaV2
- ONNX Runtime
- OpenVINO
- ROCm stack
- Milvus/Weaviate
- DeepEval/promptfoo

## 15. 结论

LocalAIStack 2.0 的 upstream 策略应该是：

```text
P0 项目用于构建 Express 可运行路线。
P1 项目用于支撑 RAG/Search 应用层。
P2 项目用于 Expert 的高级优化、插件化和长期竞争力。
```

第一阶段不要追求“项目最多”，而要追求“verified recipes 最可靠”。项目列表的作用不是堆生态，而是帮助 LocalAIStack 逐步建立可引用、可复现、可演进的本地 AI 应用栈。
